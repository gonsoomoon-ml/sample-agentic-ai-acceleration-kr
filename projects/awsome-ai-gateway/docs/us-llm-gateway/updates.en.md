## Why · pitfalls (per item)

- **US-14** — Windows installer for Claude Code: replaces Python, git, `pip install` and PATH edits on each employee PC with **one installer file** — build PC (`site-config.json`, 4 values) → `gateway-cli-setup-<ver>.exe` → install on the employee PC + `gateway-cli setup` (writes `apiKeyHelper`, `env` and `model` into `C:\Program Files\ClaudeCode\managed-settings.json`) + Claude Code install and `gateway-cli login` in the user's own session. No gateway or chart change. Traps: an unsigned exe trips SmartScreen · `setup` needs an administrator window · `setup` also persists the OIDC values as user environment variables, which breaks key issuance if Cowork on the same PC points at a different deployment (`--no-persist-env`) · the sign-in callback port must be one of the registered 8090·8091 · the installer source lives on the `feat/cc-installer-import` branch (vendor 0.2.0 with four customer identifiers replaced by placeholders; never merged into `us/deploy-fixes`).
- **US-13** — `us.anthropic.claude-opus-5-5` is ACTIVE in Bedrock us-west-2 (`global.` too). Alias `claude-opus-5-5`, provider id `us.anthropic.claude-opus-5-5`. Rates come from the first-party list price ($4/$20 per MTok) plus the 10% geographic-endpoint premium: **input `0.004400`, output `0.022000`, 5m cache `0.005500`, 1h cache `0.008800`, cache read `0.000220`** (USD per 1K tokens). ⚠️ **The cache-read multiplier differs** — Opus 5.5 charges 0.05x the input price where every other model charges 0.1x, so the usual formula records twice the real cost. The AWS Pricing API still has no new models (us-west-2 Anthropic SKUs stop at Claude 3), so verify against Cost Explorer after registering. Model behaviour: disabling thinking returns 400, forced `tool_choice` returns 400, and the default effort is `medium` (Opus 5 uses `high`) — all client-side, no gateway change. Clients need no change either: with no model roster pinned, the alias appears once the 5-minute `model:list` cache expires. The fallback chain is global, so registering it needs a gateway-proxy restart, and **apps with web search enabled may not fall back at all** because of the fork's bypass bug. Once this is verified, `claude-opus-4-8` goes INACTIVE (9 requests in 30 days, 18 in 90, last used 2026-08-26, and its rates were seeded at global instead of geographic prices).
- **US-12** — admin-ui has carried the Cognito sign-in code since US-10 (Authorization Code + PKCE, `/api/auth/login`·`/api/auth/callback`), but with no configuration it fell through to the development login form — pick a role and you get an unsigned ADMIN token. Turning it on = add the callback `https://<admin-ui host>/api/auth/callback` to the Cognito app client (the same one `gateway-cli` uses; tfvars `cognito_callback_urls` → terraform, keep the 3 localhost entries) · 4 `OIDC_*` lines in values `adminUi.env` · `DEV_LOGIN_ENABLED` `"false"` in both admin-api and admin-ui. `19-admin-login.sh` computes all of it from terraform output and the Ingress. Pitfalls: ① callbacks must be https (localhost excepted) → US-06 first ② an admin missing from `auth.users` (never signed in to the gateway) gets 403 `user_not_provisioned` right after sign-in ③ turning dev-login off first locks everyone out → turn it off after the sign-in is verified (`19` refuses otherwise) ④ once sign-in is on, `/` goes to Cognito and the development login opens only by typing `/api/auth/dev-login` ⑤ session = Cognito id_token, 1 hour. `status.sh` judges US-12. Procedure: [8-L](ops/8-L-admin-login.md).
- **US-11** — Gateway prices must equal what AWS bills, or team budgets and ROI drift. `us.anthropic.*` (geographic CRIS) is billed at the Price List **Standard** tier (Global ×1.1) — measured in account 891 Cost Explorer (per 1M): Opus 5 $5.50/$27.50 · Sonnet 5 $2.20/$11 · Haiku 4.5 $1.10/$5.50. The old rows carried Global prices (Opus 5 10% under), and Sonnet 5 had the launch-time Sept-1 increase ($3/$15) pre-applied even though Anthropic **cancelled** it (36% over). Source of truth is `update-scripts/pricing.tsv`; `08` closes the open row and inserts a new one (`effective_from` = apply time — past `usage_logs` are not recomputed). Pitfall: Redis caches `model:{alias}` for 300s, so allow 5 minutes; restarting pods does nothing. Upstream migration 0030 seeds Sonnet 5 at the Global $2/$10, so re-run `08` after an upstream sync. A deployment whose alias points at a `global.*` profile first moves it to `us.*` with `02 --remap` (the routing rows of `14` tell you). Full procedure: [8-R](ops/8-R-pricing.md).
- **US-10** — A full refresh of upstream code — per-app model allow-list (0035) · system settings table (0036) · body logging with all three switches OFF · duplicate-guarding unique indexes (0034) · installer · UI translations, plus 13 fixes (Sept 14–15, 2026). What touches US directly: `/health/ready` returned 503 on Redis degradation, so every pod left the ALB at once · Claude Code sending thinking `enabled` got 400 everywhere · six web-search loop defects (forced last turn 400 · leaked `tool_use` causing resends · unbounded search count) · cost-recorder double charge / lost PEL batches · budget DB fallback ignoring policy. Traps: ① rebuilding under the same tag makes helm rollback meaningless → bump tags with `13` first ② the migration runs before the rollout, so old pods may fail model-list reads for a few minutes until new pods are Ready — do not roll back in that window ③ 0027 seeds `global.anthropic.*` full-ID aliases as ACTIVE → set INACTIVE in the admin UI (`14` reports them) ④ helm rollback does not undo the schema → take the DB snapshot first (8-D ③) ⑤ terraform: plan only (no apply needed · re-enabling the ESO webhook is a separate decision). **Added Sept 16**: web-search cost caps (`17-set-websearch-caps.sh`, 8-D ②) — search results are fed back into every later turn and billed again, so one search question cost $3.62; four caps cut that by ~60%. Deployments that finished US-10 on Sept 15 only add `17 --apply` → `install-eks.sh`. **Added Sept 19**: web-search improvements — the app sends the search record back as is, so follow-ups like "what was the source?" are answered without searching again (Cowork · Claude Code) · when the model calls app tools (file save, task list) and a search in the same turn, both run · app tools keep working after the search budget is used up (saving a file after searching no longer breaks) · defaults are built into the code, so it works without `17` (3 searches per turn · 2 turns · 5 results; `17` only to change them). Two stability fixes: when Claude Code sent its advisor tool, Bedrock rejected every request with 400 (the gateway now removes just that tool) · the first non-streaming request after hours of idle returned 502 (one connection retry — measured after 8.8 idle hours: 2 retries, all 200). How it works: [web-search-explained.md](web-search/web-search-explained.md). Deployments that finished US-10 before Sept 19 only rebuild the gateway-proxy image → `install-eks.sh` (no DB change).
- **US-09** — Cowork Windows installer: instead of the manual guide (6 registry keys typed by hand) the admin builds **one installer file** — build PC (`site-config.json` = output of `07-client-values.sh`) → `gateway-cli-cowork-setup-<ver>.exe` → on each employee PC install + `gateway-cli-cowork setup` (HKLM `Policies\Claude` inference* ×6, machine-wide) → the user installs Claude Desktop (offline .msix) and runs `login`. No gateway or chart change. Pitfalls: HKLM policy means dev and prod cannot coexist on one PC · the Cowork sandbox needs Hyper-V (on EC2: metal + `VirtualMachinePlatform`·`Containers`) · `winget` needs `--source winget` · code lives on branch `feat/cowork-installer-import`. Order: [admin E2E](cowork/installer/cowork-installer-admin-e2e-windows.md) → [build](cowork/installer/cowork-installer-build-windows.md) · [user](cowork/installer/cowork-installer-user-windows.md) · [uninstall](cowork/installer/cowork-installer-uninstall-windows.md).
- **US-08** — Production: not a switch on dev but a **new stack in a separate account** (`environment = "prod"` = HA sizing). Built as https (US-06) + admin internal (US-07) from the start, so **the VPN comes first** — without it VK issuance is blocked (verified with AWS Client VPN as a stand-in). Pitfalls: network CIDRs must not overlap dev (VPN routing) · prod values image tags and `elasticache_endpoint` (cluster mode) need the 2026-08 fixes · the Cowork Windows test machine must be metal (Hyper-V). Details: [8-P §5](ops/8-P-prod.md).
- **US-07** — Final customer posture: move the control-plane ALBs (admin-api · admin-ui) to internal in the private subnets, reachable only over the site-to-site VPN; the data plane (gateway) stays public. No terraform change — the vpc module already creates the subnets and tags. New installs include it during `US-01` (uncomment the values at §3-6, no extra steps — see the note in install-guide §3-6); running deployments follow the [§8-I runbook](ops/8-I-admin-internal.md) — an ALB recreation, so swap the admin CNAMEs (a few minutes of admin downtime). ⚠️ Applying without the VPN breaks VK issuance (api-key-helper → admin-api) and thus the gateway itself — do not apply before the VPN exists. Internal ALB creation and in-VPC reachability were verified by rehearsal (2026-08-20).
- **US-06** — Serve the 3 ALBs as `https://gateway-<env>.<domain>` instead of http:80 on the temporary ALB address: TLS terminated at ACM, a fixed name, no CloudFront needed for Cowork. If your account cannot register domains (e.g. Amazon-internal), register in another account and delegate NS. Afterwards replace `ANTHROPIC_BASE_URL` · `ADMIN_API_URL` on clients.
- **US-05** — 1.31 is past standard support: extended-support surcharge (~$365/month per cluster) and after end of support (2026-11-26) AWS force-upgrades automatically. One minor version at a time (3 applies); restart pods in every namespace after each step (on Fargate a pod is a node).
- **US-04** — Bedrock · STS calls go over PrivateLink inside the VPC instead of NAT + public internet. Only VPCs created before the endpoint declaration existed are affected (new installs already include it) — nothing tells you, Bedrock keeps working. Restart gateway-proxy right after applying: dead sockets left in the pool cause consecutive 502s that look like the endpoint is broken.
- **US-03** — Admin console i18n; the KO/EN toggle in the header actually translates. Needs an admin-ui image rebuild.
- **US-02** — The install migration seeds the Cowork routing row with a non-existent account, so left as is every Cowork request is a 502 (`01`). `02` enables Opus 5 — the seed registers the alias as global.*, so `--remap` switches it to US Geo. Prices come from §4-2 (C) and `08` (missing prices record cost as `$0` and bypass budgets). `03` CloudFront only when you need https for Cowork without a domain (not needed with US-06). **A new install (US-01) already includes 01 and 02 via §4-2·§4-3**, so only 03 applies.
- **US-01** — Baseline: single account · us-west-2 · Claude Code · US Geo inference.
