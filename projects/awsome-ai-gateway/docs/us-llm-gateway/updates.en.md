## Why · pitfalls (per item)

- **US-20** — One batch of outside contributions (fork PR). Changes not in the table: key (VK) lifecycle (a repeat issue for the same user within 5 seconds reuses the existing key · a revoke alert event · a scheduler that deletes expired keys, off by default `KEY_PURGE_ENABLED`) · one rule for the admin console language · the Revoke button disabled on expired keys · a Marketplace subscription doc for when a new model's first call is AccessDenied ([8-Q](ops/8-Q-marketplace.md)). Pitfalls: ① logout goes through Cognito `/logout`, so if the admin console address is not in the app client's Allowed sign-out URLs, logout stops on a Cognito error — register it with `19 callback` before the new admin-ui (in a hurry, admin-ui env `OIDC_LOGOUT_URL=off` goes back to clearing only the cookie) ② the downgrade 400 fix removes only the fields the older model does not accept — models that accept them (Opus 5.5 · Sonnet 5.5) are left as they are ③ turning on body logging keeps employees' full prompts and responses (including local paths) in S3 for 90 days — turn it on after a privacy review; turning it off also needs the confirm dialog of the admin console toggle ④ alert email defaults to mock (nothing is sent), and the `SES` line of `status.sh` says so. `status.sh` judges US-20 (tags of the 3 running images · logout URL registered).
- **US-19** — `us.anthropic.claude-haiku-5-5` is ACTIVE in Bedrock us-west-2 (`INFERENCE_PROFILE` only, so `us.` is required; AUTHORIZED in both 891 and 738). Prices (per 1K tokens, matching the Price List `_standard` SKUs) are **input `0.000110` · output `0.000550` · cache 5m `0.0001375` · 1h `0.000220` · read `0.000011`**, and **when one request's prompt (input + cache write + cache read) exceeds 100K tokens, the whole request is billed at 5x** (`*_long_ctx_standard`). What changed: ① the gateway's thinking normalizer treated any alias containing `haiku` as Haiku 4.5 and rewrote `adaptive` into `enabled` + `budget_tokens`, which Bedrock rejects with 400 (`"thinking.type.enabled" is not supported`) — Haiku 5.5 is now adaptive, and the alias guess runs only when there is no model ID and reads the version (the same fix as canonical phase-2) ② price columns widened from 6 to 8 decimals (the 5m cache write has 7) — the same change as canonical 0043, done as an idempotent block in the init SQL so it takes no alembic number (avoids numbering clashes) ③ `pricing.tsv` has 14 columns (`long_*` × 6) and `08` · `14` · `status.sh` handle the long-prompt rates; PostgreSQL rounds a longer price without an error, so `02` · `08` check the decimal places first ④ editing a price in the admin UI keeps the long-prompt rates (the new row used to drop them) ⑤ `haiku-5*` added to the IAM default list (US deployments use a wildcard in tfvars, so nothing changes). Haiku 4.5 stays because it is the default model for background tasks in Claude Code (checked on 2.1.293) and Cowork. Postponed: long-prompt rate fields in the admin UI · automatic Claude price sync (today's button cannot find Claude prices) · long-prompt rates in the pre-reservation cost estimate.
- **US-18** — 2 upstream (aws-samples) changes from 9/23 + 7 fixes contributed to this fork (fork PR) + 1 price. Budget alert thresholds are stored in the DB (migration 0037 — before, they reverted to 80/90/100 when the 5-minute Redis config expired) · the long-prompt price tier framework (0038·0039 — values only for GPT 5.6, Claude prices unchanged; a prerequisite for registering Haiku 5.5) · team-budget threshold alerts are sent and the email shows the period-to-date usage · a team leader can no longer read other teams' budgets through the API (the direct-API path, not the admin UI) · the member table on a team leader's Budgets page (when a member used Claude Code, Cowork or Codex that month, usage matched both the total row and a per-app row, and the lookup returned 500) · the allowed-users list on the app policy page (users with no restriction were left out, so it showed "No allowed users." — it now follows the gateway's actual allow rule) · gateway-proxy follows `REPORTING_TIMEZONE` too (no change for Asia/Seoul deployments) · `ttft_ms` is recorded on the web search path (it was always NULL) · the analytics cache (a re-open within 30 s got a string and broke the screen; the app filter was ignored) · Sonnet 5.5 cache read $0.22→$0.11/1M (Bedrock pricing page footnote "Starting October 7"). Pitfalls: ① there are DB changes, so shipping this code the 8-A/8-U way (gateway-proxy only) makes new pods read columns that do not exist — always use 8-D ② the price applies from the moment you run it (records between 10/7 and then are not recalculated); check Cost Explorer the next day ③ the DB changes only add columns, so a helm rollback to the old images still works, but take the snapshot first ④ team alert recipients = the user who sent the request + the team leader (default notification config). `status.sh` reports US-18 (schema 0039 · Sonnet 5.5 cache read = `pricing.tsv`).
- **US-17** — Claude Code sends feature names in the `anthropic-beta` header; Bedrock takes them only in the body (`anthropic_beta`) and rejects the whole request with a 400 if a single name is unknown. So the gateway forwards only the four that passed testing (`dangerous-tool-use` with the body's `safeguards` · `per-turn-control` · `inline-tools` · `thinking-display-updates`) and drops the rest — the list is the `BEDROCK_FORWARD_BETAS` setting, and per-beta test records are in [beta-headers](beta-headers/README.md) (Korean). Pitfalls: ① when a request carrying the classifier beta gets a 400 Claude Code does not recognise, that conversation switches to the PC-side classifier for good, with no notice — a new 400 caused by the gateway silently turns server verdicts off ② when server verdicts work, Claude Code records them nowhere — verify with `check-safeguards-passthrough.py` (5 PASS) and the Bedrock invocation log ③ updating Claude Code brings new betas — watch `upstream_compat.beta_dropped` and `bedrock_*client_error` in the gateway log.
- **US-16** — `us.anthropic.claude-sonnet-5-5` is ACTIVE in Bedrock us-west-2 (`global.` too). It is `INFERENCE_PROFILE`-only, so the `us.` prefix is required. Rates come from the first-party list price ($2/$10 per MTok) plus the 10% geographic-endpoint premium: **input `0.002200`, output `0.011000`, 5m cache `0.002750`, 1h cache `0.004400`, cache read `0.000220`** (USD per 1K tokens); cache read is the usual 0.1x (only Opus 5.5 is 0.05x). The values live in `update-scripts/pricing.tsv` and the commented block in `config.env.example`; verify against Cost Explorer after registering. Model behaviour: disabling thinking (`disabled`) returns 400 (use `between_tools` to turn it off), forced `tool_choice` returns 400, and the effort levels are recalibrated from Sonnet 5 — all client-side, so the gateway does not change. **This deployment keeps only the latest models** — Opus 5.5 · Sonnet 5.5 · Haiku 4.5, with the fallback `claude-opus-5-5 → claude-sonnet-5-5`. ⚠️ **Keep the order**: register → switch employee PCs' default model (`gateway-cli setup --model claude-sonnet-5-5` on PCs set up with the Claude Code installer, `gateway-cli-cowork setup` for Cowork) → deactivate the previous generation. Deactivating first breaks every PC whose default is pinned to `claude-sonnet-5`. Check the client floor with the first call after registering (Opus 5.5 needs 2.1.280). Fresh-install defects fixed along the way: in install-guide §4-2, step (D) of the same SQL deactivated the Opus 5.5 it had just registered, and there was no Opus 5.5 price row — sites installed with that SQL should check the US-13 line of `status.sh`.
- **US-15** — The VK is the gateway key issued by admin-api; by default the helper silently renews it every hour. Raising it to 24 hours makes renewal once a day, removing the delay at that moment and the admin-api calls; the Cognito sign-in period (7 days) and the id_token (1 hour) are unchanged. The knob is one values line, `adminApi.oidc.vkTtlHours` — putting it under `adminApi.env` creates two env entries with the same name, so that is not the supported path. Any whole number of hours works (e.g. 12), not only 24. Applies to newly issued keys; existing 1-hour keys are renewed 5 minutes before expiry, so everyone is on 24 hours within an hour. Pitfalls: the exposure window if a key leaks grows to 24 hours · a user's group (team) change takes up to 25 hours to show · after a renewal the old key still passes until its remaining lifetime ends (admin revocation stays immediate and deactivation takes effect within 5 minutes) · after refreshing the repository (`reset --hard`) run `terraform init` first, or the deploy script stops with `terraform output 실패`.
- **US-14** — Windows installer for Claude Code: replaces Python, git, `pip install` and PATH edits on each employee PC with **one installer file** — build PC (`site-config.json`, 4 values) → `gateway-cli-setup-<ver>.exe` → install on the employee PC + `gateway-cli setup` (writes `apiKeyHelper`, `env` and `model` into `C:\Program Files\ClaudeCode\managed-settings.json`) + Claude Code install and `gateway-cli login` in the user's own session. No gateway or chart change. Traps: an unsigned exe trips SmartScreen · `setup` needs an administrator window · `setup` also persists the OIDC values as user environment variables, which breaks key issuance if Cowork on the same PC points at a different deployment (`--no-persist-env`) · the sign-in callback port must be one of the registered 8090·8091 · the installer source lives on the `feat/cc-installer-import` branch (vendor 0.2.0 with four customer identifiers replaced by placeholders; never merged into `us/deploy-fixes`).
- **US-13** — `us.anthropic.claude-opus-5-5` is ACTIVE in Bedrock us-west-2 (`global.` too). Alias `claude-opus-5-5`, provider id `us.anthropic.claude-opus-5-5`. Rates come from the first-party list price ($4/$20 per MTok) plus the 10% geographic-endpoint premium: **input `0.004400`, output `0.022000`, 5m cache `0.005500`, 1h cache `0.008800`, cache read `0.000220`** (USD per 1K tokens). ⚠️ **The cache-read multiplier differs** — Opus 5.5 charges 0.05x the input price where every other model charges 0.1x, so the usual formula records twice the real cost. The AWS Pricing API still has no new models (us-west-2 Anthropic SKUs stop at Claude 3), so verify against Cost Explorer after registering. Model behaviour: disabling thinking returns 400, forced `tool_choice` returns 400, and the default effort is `medium` (Opus 5 uses `high`) — all client-side, no gateway change. Clients need no change either: with no model roster pinned, the alias appears once the 5-minute `model:list` cache expires. The fallback chain is global, so registering it needs a gateway-proxy restart, and **apps with web search enabled may not fall back at all** because of the fork's bypass bug. Once this is verified, `claude-opus-4-8` goes INACTIVE (9 requests in 30 days, 18 in 90, last used 2026-08-26, and its rates were seeded at global instead of geographic prices). ⚠️ **It has a client floor** — anything below Claude Code 2.1.280 (including the copy embedded in Claude Desktop) is refused by Bedrock with a 400 (`does not support this model; version 2.1.280 or newer is required`). That is a client problem, not a registration one: run `claude update`, or install a newer offline `.msix` for Cowork.
- **US-12** — admin-ui has carried the Cognito sign-in code since US-10 (Authorization Code + PKCE, `/api/auth/login`·`/api/auth/callback`), but with no configuration it fell through to the development login form — pick a role and you get an unsigned ADMIN token. Turning it on = add the callback `https://<admin-ui host>/api/auth/callback` to the Cognito app client (the same one `gateway-cli` uses; tfvars `cognito_callback_urls` → terraform, keep the 3 localhost entries) · 4 `OIDC_*` lines in values `adminUi.env` · `DEV_LOGIN_ENABLED` `"false"` in both admin-api and admin-ui. `19-admin-login.sh` computes all of it from terraform output and the Ingress. Pitfalls: ① callbacks must be https (localhost excepted) → US-06 first ② an admin missing from `auth.users` (never signed in to the gateway) gets 403 `user_not_provisioned` right after sign-in ③ turning dev-login off first locks everyone out → turn it off after the sign-in is verified (`19` refuses otherwise) ④ once sign-in is on, `/` goes to Cognito and the development login opens only by typing `/api/auth/dev-login` ⑤ session = Cognito id_token, 1 hour. `status.sh` judges US-12. Needs admin-api `1.0.69-idpjwks` — earlier versions verified the console token only against static keys in `admin_jwt_configs`, so on an install with just the seeded placeholder key every API call after sign-in was a 500 (measured on US dev). From this version the token is verified with the IdP's JWKS; `aud` is checked at the same level as VK issuance (only when configured). Procedure: [8-L](ops/8-L-admin-login.md).
- **US-11** — Gateway prices must equal what AWS bills, or team budgets and ROI drift. `us.anthropic.*` (geographic CRIS) is billed at the Price List **Standard** tier (Global ×1.1) — measured in account 891 Cost Explorer (per 1M): Opus 5 $5.50/$27.50 · Sonnet 5 $2.20/$11 · Haiku 4.5 $1.10/$5.50. The old rows carried Global prices (Opus 5 10% under), and Sonnet 5 had the launch-time Sept-1 increase ($3/$15) pre-applied even though Anthropic **cancelled** it (36% over). Source of truth is `update-scripts/pricing.tsv`; `08` closes the open row and inserts a new one (`effective_from` = apply time — past `usage_logs` are not recomputed). Pitfall: Redis caches `model:{alias}` for 300s, so allow 5 minutes; restarting pods does nothing. Upstream migration 0030 seeds Sonnet 5 at the Global $2/$10, so re-run `08` after an upstream sync. A deployment whose alias points at a `global.*` profile first moves it to `us.*` with `02 --remap` (the routing rows of `14` tell you). Full procedure: [8-R](ops/8-R-pricing.md).
- **US-10** — A full refresh of upstream code — per-app model allow-list (0035) · system settings table (0036) · body logging with all three switches OFF · duplicate-guarding unique indexes (0034) · installer · UI translations, plus 13 fixes (Sept 14–15, 2026). Traps: ① rebuilding under the same tag makes helm rollback meaningless → bump tags with `13` first ② the migration runs before the rollout, so old pods may fail model-list reads for a few minutes until new pods are Ready — do not roll back in that window ③ 0027 seeds `global.anthropic.*` full-ID aliases as ACTIVE → set INACTIVE in the admin UI (`14` reports them) ④ helm rollback does not undo the schema → take the DB snapshot first (8-D step 3) ⑤ terraform: plan only (no apply needed · re-enabling the ESO webhook is a separate decision). **Added Sept 16**: web-search cost caps (`17-set-websearch-caps.sh`, 8-D step 2) — search results are fed back into every later turn and billed again, so one search question cost $3.62; four caps cut that by ~60%. Deployments that finished US-10 on Sept 15 only add `17 --apply` → `install-eks.sh`. **Added Sept 19**: web-search improvements — the app sends the search record back as is, so follow-ups like "what was the source?" are answered without searching again (Cowork · Claude Code) · when the model calls app tools (file save, task list) and a search in the same turn, both run · app tools keep working after the search budget is used up (saving a file after searching no longer breaks) · defaults are built into the code, so it works without `17` (3 searches per turn · 2 turns · 5 results; `17` only to change them).
